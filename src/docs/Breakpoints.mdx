# Breakpoints

Cast UI ships a small set of breakpoints and hooks for building layouts that
adapt across phones, tablets, and desktops. The values follow the Material 3
window size classes, which are based on real device-width data, so the same
numbers hold up across watches, phones, foldables, tablets, and large screens.

Breakpoints are a standalone foundation. They are not part of `ThemeProvider`,
they do not change with density or brand colours, and they are not carried in a
`cast-theme.json`. The scale stays identical in every app.

**Quick reference:**

| You want to… | Do this |
|---|---|
| Know the current tier | `useBreakpoint()` returns `'base' \| 'sm' \| 'md' \| 'lg' \| 'xl'` |
| Pick a value per tier | `useResponsiveValue({ base: 1, md: 2, xl: 4 })` |
| Check a minimum width | `useMinWidth('lg')` returns a boolean |
| Read a raw threshold | Import the `breakpoints` object |

---

## The scale

All values are minimum widths in density-independent pixels (dp). A width is
"at" a tier when it is greater than or equal to that tier's value. Anything
below `sm` is the implicit `base` tier.

| Tier | Range (dp) | Typical devices |
|---|---|---|
| `base` | `< 600` | Watches and every phone in portrait. iPhone SE 320 up to Pro Max 430. Your default layout. |
| `sm` | `>= 600` | Large phones in landscape, foldables unfolded, small tablets in portrait |
| `md` | `>= 840` | Tablets. iPad landscape and larger |
| `lg` | `>= 1200` | Laptops and desktops |
| `xl` | `>= 1600` | Large desktops and TVs |

The same values live as the `breakpoint/*` primitive variables in the
[cast-ui-kit Figma file](https://www.figma.com/design/JGtlpxLPJMZcwvQ3UZ9ZUl/cast-ui-kit),
so design and code share one scale.

---

## Reading the current breakpoint

`useBreakpoint` returns the active tier for the current window width. It reads
the live window, so it updates on resize, rotation, and foldables, and it
behaves the same on the web.

```tsx
import { useBreakpoint } from '@castui/cast-ui';

function Header() {
  const tier = useBreakpoint(); // 'base' | 'sm' | 'md' | 'lg' | 'xl'
  return tier === 'base' ? <CompactHeader /> : <FullHeader />;
}
```

---

## Choosing a value per breakpoint

`useResponsiveValue` picks a value for the current tier. It is mobile-first: a
tier with no value falls back to the nearest one defined below it. So
`{ base: 1, md: 2 }` gives 1 from `base` up to `md`, then 2 from `md` on.

```tsx
import { useResponsiveValue } from '@castui/cast-ui';

function Gallery() {
  const columns = useResponsiveValue({ base: 1, md: 2, xl: 4 });
  // 1 column on phones, 2 on tablets, 4 on large desktops
  return <Grid columns={columns} />;
}
```

You only set the tiers where the value changes. Everything in between inherits
from the tier below.

---

## Checking a minimum width

`useMinWidth` is a simple boolean for "this width and up". Use it to show or
hide a whole piece of UI.

```tsx
import { useMinWidth } from '@castui/cast-ui';

function Layout() {
  const showSidebar = useMinWidth('lg'); // true from 1200dp up
  return (
    <Row>
      {showSidebar && <Sidebar />}
      <Content />
    </Row>
  );
}
```

---

## The raw values

If you need a threshold directly, import the `breakpoints` object.

```tsx
import { breakpoints } from '@castui/cast-ui';

breakpoints.md; // 840
```

---

## How it behaves

React Native has no CSS media queries, so a breakpoint here is a width
threshold you compare against, not automatic restyling. The hooks give you the
current tier or a value for it, and you apply the layout yourself.

`base` is the mobile-first default. You write the phone layout with no
breakpoint, then add overrides for larger screens.

The gap between a small phone and a large phone is better handled with flexible
layout, such as `flex`, percentage widths, and `maxWidth`, than with a
breakpoint. A watch is its own surface, not a tier, so it falls into `base` and
shares the default layout.

---

## A fixed foundation

Breakpoints are deliberately kept out of the theme. Colours and spacing can be
themed per app through `ThemeProvider` and the cast-sync plugin, but a layout
breakpoint is structural, not brand. Keeping it fixed means the points at which
a layout reflows are the same in every app that uses Cast UI, which keeps things
predictable. If you ever need app-specific thresholds, compare the window width
against your own numbers directly rather than overriding the scale.
